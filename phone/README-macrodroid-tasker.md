# Phone remote: switch earbuds between PC and phone

Two layers, pick either or both.

## A. KDE Connect run commands (manual buttons)

On the PC, KDE Connect Settings → Run commands, add (commands run on the PC):

| Name | Command |
|---|---|
| 🎧 PC only | `~/.local/bin/bluetooth-toggle.sh on` |
| 📱 Phone only | `~/.local/bin/bluetooth-toggle.sh release` |
| 📵 Bluetooth Off | `~/.local/bin/bluetooth-toggle.sh off` |

On Android: open the device → Run commands. For home-screen one-tap buttons:
long-press home → Widgets → KDE Connect → Run command → pick device + command.
The PC pings the phone on every switch, so both sides confirm.

## B. Intent push via MacroDroid / Tasker (automatic)

Needs: PC reachable on LAN (DHCP reservation recommended), TCP **8899**
open on the PC firewall, token from `~/.config/bt-intent.token`
(generated by install.sh). Base: `http://PC_IP:8899`.

| Phone event | GET endpoint | PC does |
|---|---|---|
| Music playing (BT connected to buds) | `/phone_playing?token=...` | parks PC audio, hands off 4h |
| Music paused/stopped | `/phone_paused?token=...` | clears hands-off (PC may grab back) |
| Call started | `/call_start?token=...` | parks PC audio, hands off 2h |
| Call ended | `/call_end?token=...` | clears hands-off |
| (test) | `/health?token=...` | returns `ok` |

MacroDroid (free tier fits: 4 macros): Triggers `Music/Sound Playing`
(Playing/Stopped), `Call Active` (Any), `Call Ended`; Constraint Bluetooth
connected to your buds; Action `HTTP Request` GET to the URLs above.
Set MacroDroid battery to Unrestricted or Samsung kills it.

Tasker (paid, no ads): same mapping with State `BT Connected` +
Event `UI → Notification` (Posted/Removed, music apps) for media,
State `Phone → Call` / Event `Phone Idle` for calls, task
`Net → HTTP Request` GET. Needs notification access + unrestricted battery.

Security note: token in plain HTTP on your home LAN. Anyone on the LAN
with the token can flip your audio — fine at home, don't expose 8899
to the internet.
